第1章：开篇 - 问题分析与解决策略

章节类型：思想篇 - 编程的思维方式

一、核心观点

1.1 思考优于编码

"编程的本质是思考，而不是打字。"

在写第一行代码之前，需要：

  1. 理解问题 - 真正明白要解决什么
  2. 分析约束 - 资源限制、时间要求
  3. 设计方案 - 画出思路再动手

1.2 简单性原则

KISS 原则（Keep It Simple, Stupid）：

// 复杂实现
class ComplexProcessor {
  private strategy: any;
  private cache: Map<any, any>;
  private observers: Observer[];

  process(data: any): any {
    // 200 行代码...
  }
}

// 简单实现
function process(data: number[]): number {
  return data.reduce((a, b) => a + b, 0);
}

二、问题解决策略

2.1 理解问题的三个层次

层次 问题 示例
表层 用户说的 "我要排序功能"
中层 实际需求 "需要对用户列表按年龄排序"
深层 根本目的 "展示最新注册的用户"

2.2 问正确的问题

// ❌ 错误：直接开始编码
function sort(arr) {
  return arr.sort();
}

// ✅ 正确：先问问题
// 1. 什么类型的数据？数字？字符串？对象？
// 2. 升序还是降序？
// 3. 数据量多大？100条还是100万条？
4. 是否需要稳定排序？
// 5. 是否有重复元素？
// 6. 原地排序还是允许新数组？

三、著名问题：90-90 法则

"前 90% 的代码占用了 90% 的开发时间。剩下的 10% 代码又占用了另外 90% 的开发时间。"

应对策略

  1. 早思考 - 在写代码之前充分思考
  2. 多迭代 - 小步快跑，持续改进
  3. 留扩展 - 考虑未来需求变化
// 迭代式开发 vs 一次性完美

// 迭代式：先简单，再优化
// v1: 基础功能
function search(arr, target) {
  return arr.indexOf(target);
}

// v2: 性能优化 - 二分搜索
function search(arr, target) {
  let left = 0, right = arr.length - 1;
  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}

四、练习题

练习 1.1：问题分析

用户说："帮我做一个排序功能，按销售量排序。"

请分析：

  1. 表层需求是什么？
  2. 实际需求可能是什么？
  3. 需要问哪些问题？

练习 1.2：简化问题

将以下复杂问题简化为核心问题：

  1. "我需要一个大数据处理系统，能实时分析用户行为"
  2. "做一个推荐系统，类似于抖音"

练习 1.3：代码评审

以下代码有什么问题？应该问什么问题？

function getUser(id) {
  return database.query("SELECT * FROM users WHERE id = " + id);
}

五、答案提示

练习 1.1 参考

  • 表层：排序功能
  • 实际：按销售量降序排列商品列表
  • 问题：
    • 数据来源是什么？数据库？API？
    • 销售量字段名？ sales? volume?
    • 是否需要分页？
    • 相同销售量如何处理？

练习 1.3 参考

  • SQL 注入风险！
  • 没有错误处理
  • 没有类型定义
  • 数据库连接未处理
  • 返回格式不明确
